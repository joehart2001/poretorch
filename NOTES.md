# Build notes

> Historical snapshot from the initial build. The release state and limitations
> below describe 2026-08-21 and may have since been addressed.

Working notes from the initial build of PoreTorch on 2026-08-21. Scratch record
of what was decided and why, not user-facing documentation. The user-facing
material is `README.md` and `docs/source/`.

## Where this came from

PoreTorch packages the pore-analysis code that had accumulated in
`/home/jh2536/amorphous-carbon/analysis_scripts/pore_analysis` as a set of
scripts across several generations (`identify_pores_v1.py`,
`identify_pores_PBC.py`, `identify_pores_with_overlap.py`,
`poreblazer_method.py`, `compute_pore_radii_{1,2,cpu}.py`, plus batch runners
and figure scripts). The repository is modelled on `/home/jh2536/curdf`, matching
its layout, docstring style, packaging and test conventions.

## Decisions taken at the start

Three questions were settled before any code was written, since each would have
changed the work substantially.

**Scope.** The three pore-size definitions plus pore labelling. Deliberately
left out, and still available in the old scripts if wanted later:
`specific_surface_area.py` (Monte-Carlo, grid and pore-volume SSA),
`gyration_tensor.py` (per-pore shape descriptors), and the subprocess wrapper
around the real `poreblazer_intel.exe`.

**Distance-field backend.** Cell-list accelerated with a brute-force reference
path, and a test that the two agree. Rejected: porting the brute-force kernel
alone, which stays quadratic in the atom count.

**Cell geometry.** Full triclinic support. Rejected: orthorhombic-only with an
explicit error, which is what the old code actually supported correctly.

## Deliberate departures from the old scripts

These are behaviour changes, not ports. Each was a bug or an inconsistency in
the scripts.

**Minimum image.** The scripts use `diff - L * round(diff / L)`, which is only
the shortest vector when the cell is close to orthogonal and silently wrong when
skewed. PoreTorch reduces the cell to a Minkowski-reduced basis, wraps into it,
then searches the 27 surrounding images, which is exact in three dimensions. This
is the same route `ase.geometry.find_mic` takes. Orthogonal cells skip the image
search, since the wrap alone is already exact for them.

**Grid tiles the cell.** The scripts build the grid with
`linspace(0.5 h, L - 0.5 h, floor(L / h))`, which spans less than the cell while
assuming a voxel volume of `h ** 3`. For the 12x12 rho=1 test structure that
undercounts the total volume by about 1.3 per cent and biases porosity low.
PoreTorch places points at `(k + 0.5) / n` in fractional coordinates with
`n = ceil(width / spacing)`, so voxels tile the cell exactly and voxel volume is
`V_cell / (nx ny nz)` for any cell shape. A test asserts the tiling.

**Axis counts from perpendicular widths.** `V / |a_j x a_k|` rather than the
lattice-vector lengths, so resolution stays uniform in a sheared cell.

**All-void weighting.** The scripts weight every void voxel by a full sphere
volume `(4/3) pi r**3`, which double-counts heavily because neighbouring voxels
carry almost the same sphere. PoreTorch weights each voxel by its own voxel
volume, counted once. The distribution then integrates exactly to the accessible
void volume, which is checkable, and the three methods become commensurate.
Absolute `dV/dd` values will therefore not match the old CSVs. The shapes are
comparable after normalising.

**Percolation instead of face contact.** `_classify_pore_openness` calls a pore
open when it touches both faces along an axis, which a small pocket straddling a
boundary also does. PoreTorch tracks which periodic image each component was
reached in during the boundary merge, so a pore is percolating only when it
closes on itself in a *different* image. The lattice generated by those round
trips gives a dimensionality: 0 closed, 1 channel, 2 planar, 3 network.

**Probe convention fixed to one behaviour.** `compute_pore_radii_1` subtracts the
probe radius from the reported clearance, `compute_pore_radii_2` uses it only as
an accessibility threshold. Only the second is consistent with how PoreBlazer and
Zeo++ report adsorptive-accessible pore sizes, so that is the sole behaviour and
there is no flag. Documented prominently in `field.py`.

**Packing is global, not per pore.** One greedy pass over all candidates rather
than a loop over pores, which makes the no-double-counting guarantee
unconditional and removes the per-pore full-grid mask.

**Performance cleanups.** Vectorised relabelling through a lookup array instead
of `for old, new: relabeled[labels == old] = new`, which was
`O(n_labels x n_voxels)`. Per-pore statistics through `scipy.ndimage` instead of
building a full-grid mask per pore. Iterative union-find instead of recursive.
Preallocated buffers in the greedy packing loop.

**Covering-sphere early exit.** The scripts evaluate the full
`n_void x n_centres` product. PoreTorch sorts candidates by descending radius, so
the first sphere found to cover a point is already the largest that ever will and
the point leaves the search immediately. Exactness is preserved because batches
are contiguous slices of the sorted array.

## Validation performed

Recorded here because the numbers are the evidence for the claims in the README.

- Single atom, analytic: clearance equals the minimum-image distance minus the
  radius to 1.8e-15.
- Minimum image against `ase.geometry.find_mic`: agreement to 5.3e-15 on cubic,
  orthorhombic, mildly triclinic, skewed and very skewed cells. Also confirmed
  our value never exceeds the naive wrap.
- `cell_list` against `brute`: identical, difference exactly 0.0, on all cell
  shapes, with uniform and per-atom radii, with undersized bins forcing ring
  expansion, and with `max_ring=1` forcing the fallback.
- `covering` against a naive all-pairs maximum: difference exactly 0.0,
  orthorhombic and triclinic.
- Invariants: `covering >= all_void` pointwise, `all_void` and `covering` both
  conserve void volume to 1e-9 relative, packed spheres pairwise non-overlapping
  with minimum clearance +0.24 A on the test case, filling fraction 0.20 to 0.30.
- Percolation cases: isolated blob, straight channel, planar slab, fully open
  cell, boundary-straddling pocket, two separate blobs, diagonal channel at
  connectivity 1 and 3, channel with its axis made non-periodic, `min_voxels`
  filtering.

Cross-check against the old pipeline on
`create_pores/mace-mp-0a/outputs_quench/data_liquid_rho1_0.data`, 1728 atoms,
0.3 A spacing, `atom_radius=1.716`:

| probe | old porosity | new porosity | old max clearance | new max clearance |
|---|---|---|---|---|
| 0.0 | 0.47704 | 0.48368 | 4.111 | 4.125 |
| 1.657 | 0.03284 | 0.03326 | 4.111 | 4.125 |

The porosity gap is the old grid-volume inconsistency described above. The
clearance difference is below one grid spacing, as expected from different sample
points.

236 tests, all passing, CUDA tests included.

## Benchmarks

RTX 5090, random structures at 0.05 atoms per cubic Angstrom, 0.4 A grid
spacing, best of two timed runs after a warm-up. Committed in
`benchmarks/results/results.csv`.

Clearance field, `cell_list` against `brute`: 0.011 s / 0.015 s at 500 atoms,
0.038 / 0.171 at 1728, 0.215 / 3.597 at 8000, 0.334 / 14.5 at 16000, and
0.672 / 58.6 at 32000, so 87x at the top end and widening, since only brute
force carries the atom-count factor.

Distributions at 8000 atoms: `all_void` 0.012 s, `packed` 0.295 s,
`covering` 29.7 s.

One caution learned the hard way: two benchmark processes ended up on the GPU at
once during the first attempt and roughly doubled every timing. Check the GPU is
idle before trusting a run. `python -m benchmarks.benchmark --replot` redraws the
figures from the CSV without re-timing.

## Known limitation

`covering`, the PoreBlazer-comparable method, is quadratic in the number of void
points, because in the faithful mode every void point is also a candidate sphere
centre. 1.5 s at 1728 atoms, 29.7 s at 8000, impractical at 32000. The early exit
cuts the constant hard but not the scaling.

Available now: `center_mode="local_maxima"` and `center_stride`, both documented
and tested as lower bounds on the faithful result.

The proper fix, not implemented: invert the loop so each candidate only visits
grid points inside its own ball, using a coarse per-bin count of already-assigned
points to skip candidates whose ball is fully assigned. That turns the cost from
`n_void x n_candidates` into something closer to linear in `n_void`. Worth doing
before running 32x32 cells.

An exact medial-axis reduction of the candidate set was considered and rejected.
Pruning a candidate needs `|c - c'| <= r_c' - r_c`, and on a grid that holds only
to within about one grid spacing, so any useful tolerance makes the result
approximate in a way that is not cleanly bounded.

## Not done

- No `git init` and no commit.
- Package not installed. The example was run with `PYTHONPATH=.`, so it needs
  `pip install -e .` to work as written.
- Docs written but never built. `myst-parser` and `sphinx-rtd-theme` are absent
  from `venv_mace`. All 24 autodoc targets were confirmed to resolve and nothing
  exported is undocumented, but the HTML has not been rendered.
- No MDAnalysis adapter, unlike curdf. ASE readers already cover LAMMPS data and
  dump files, extended XYZ and CIF, and MDAnalysis often lacks the per-atom
  element information the radii tables need.

## House style in this repo

Prose avoids semicolons and em dashes, including in docstrings and error
messages. Error strings use a comma before the offending value, as in
`"must be > 0, got X"`, and clauses that would otherwise be joined by a
semicolon are split into separate sentences.

Written as PoreTorch in prose, metadata and the logo. Lowercase `poretorch` only
where it is code: the import name, the package directory, `packages = [...]` and
Sphinx cross-references. This follows curdf, which is `cuRDF` on PyPI and
`curdf` on import.
